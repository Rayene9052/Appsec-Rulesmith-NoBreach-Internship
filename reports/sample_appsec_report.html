Detailed Findings

Broken Object Level Authorization (IDOR)

NB-APPSEC-001
High ✓ Fixed
Endpoint: GET /profile/<user_id> Detection: DAST OWASP: A01:2021 API: API1:2023 CWE: CWE-639

Description

The profile endpoint authenticated the caller but never verified that the authenticated identity matched the requested user ID. Any authenticated user could retrieve any other user's profile by substituting a different ID.

Evidence

Request:  GET /profile/2
          Authorization: Bearer <alice_token>
Response: 200 OK
          {"id": 2, "username": "bob", "email": "bob@example.com", "role": "user"}

Remediation

if token["user_id"] != user_id and token.get("role") != "admin":
    return {"error": "forbidden"}, 403

Broken Access Control — Missing Admin Authorization

NB-APPSEC-002
Critical ✓ Fixed
Endpoint: GET /admin/users Detection: DAST OWASP: A01:2021 API: API5:2023 CWE: CWE-862

Description

The admin user-listing endpoint had no authentication or authorisation check. Any unauthenticated HTTP client received a full dump of all user records.

Evidence

Request:  GET /admin/users  (no Authorization header)
Response: 200 OK
          [{"id":1,"username":"alice","role":"user"}, {"id":2,"username":"bob",...}]

Remediation

@app.route("/admin/users")
@require_auth(roles=["admin"])
def admin_users():
    return list_all_users()

Mass Assignment

NB-APPSEC-003
High ✓ Fixed
Endpoint: PUT /profile/<user_id> Detection: DAST OWASP: A01:2021 API: API3:2023 CWE: CWE-915

Description

The profile update endpoint merged the entire request body into the stored user object without filtering. Sending {"role":"admin"} successfully elevated the caller's privileges.

Evidence

Request:  PUT /profile/1  {"role": "admin"}
Response: 200 OK  {"id":1,"username":"alice","role":"admin"}  ← role changed

Remediation

UPDATABLE_FIELDS = {"email"}
update = {k: v for k, v in body.items() if k in UPDATABLE_FIELDS}

Insecure JWT Handling

nb-jwt-alg-none-accepted · nb-jwt-hardcoded-secret
Critical ✓ Fixed
Location: auth_routes.py Detection: SAST OWASP: A02:2021 API: API2:2023 CWE: CWE-347, CWE-798

Description

Two related issues: (1) algorithms=["HS256","none"] allows forged unsigned tokens. (2) Secret hardcoded as "secret123" in source.

SAST Evidence

Line 12: SECRET = "secret123"                      ← nb-jwt-hardcoded-secret
Line 31: jwt.decode(token, SECRET, algorithms=["HS256","none"])  ← nb-jwt-alg-none-accepted

Remediation

SECRET = os.environ.get("JWT_SECRET") or secrets.token_hex(32)
jwt.decode(token, SECRET, algorithms=["HS256"])

Server-Side Template Injection (SSTI)

NB-APPSEC-006
Critical ✓ Fixed
Endpoint: POST /render Detection: DAST OWASP: A03:2021 CWE: CWE-1336

Description

User input was embedded in the Jinja2 template source string, allowing template expressions to execute. Escalation to full RCE is possible via standard Jinja2 sandbox escapes.

Evidence

Request:  POST /render  {"name": "{{7*7}}"}
Response: 200 OK  {"message": "Hello, 49!"}  ← expression evaluated

Remediation

Missing Security Headers

NB-APPSEC-007 · NB-APPSEC-008 · NB-APPSEC-009
Medium ✓ Fixed
Scope: All endpoints Detection: DAST OWASP: A05:2021 CWE: CWE-1021, CWE-693

Description

Three browser security headers absent: Content-Security-Policy, Strict-Transport-Security, and X-Content-Type-Options. Removes browser-enforced protection against XSS, SSL stripping, and MIME sniffing.

Remediation

@app.after_request
def security_headers(response):
    response.headers["X-Content-Type-Options"] = "nosniff"
    response.headers["X-Frame-Options"] = "DENY"
    response.headers["Content-Security-Policy"] = "default-src 'self'"
    response.headers["Strict-Transport-Security"] = "max-age=63072000; includeSubDomains"
    return response

XML External Entity Injection (XXE)

NB-APPSEC-011
High ✓ Fixed
Endpoint: POST /xml/parse Detection: DAST OWASP: A05:2021 CWE: CWE-611

Description

lxml XMLParser configured with resolve_entities=True. External entity declaration referencing file:///etc/os-release caused local file contents to appear in the response.

Evidence

Request body: <!ENTITY xxe SYSTEM "file:///etc/os-release"> ... &xxe;
Response:     {"parsed_text": "NAME=\"Debian GNU/Linux\"..."}  ← file read

Remediation

parser = etree.XMLParser(resolve_entities=False)

Recommendations

Immediate (pre-production)

  • 1Implement require_auth() as a blueprint-level decorator. No route should be less protected than the sensitivity of the data it returns.
  • 2Inject JWT secrets via environment variable in every deployment. Rotate any secrets ever committed to version control.
  • 3Audit the entire codebase for pickle.loads() and eval() on untrusted data and replace before any external exposure.
  • 4Audit every Template() call to confirm no user input reaches the template source string.

Short-term (next sprint)

  • 5Add the @app.after_request security headers hook to all Flask applications as a standard baseline.
  • 6Enforce extension allowlist, UUID rename, and size cap on every file upload endpoint.
  • 7Standardise on defusedxml for all XML processing across the codebase.
  • 8Add a shared validate_url() utility for all outbound request code so SSRF protection is consistent.

Ongoing

  • 9Run NoBreach AppSec Rulesmith DAST and SAST rules in CI on every pull request to catch regressions.
  • 10Integrate pip-audit for dependency vulnerability scanning in CI.
  • 11Review knowledge_base/secure-coding-checklist.md before every deployment.
